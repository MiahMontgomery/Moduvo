# Prompt for Replit Agent: Finalizing ModuvoPlatform Codebase

## Fix or Complete Existing Features

* **Pricing/Quote calculation** – The `calculateQuote` logic in `server/routes.ts` currently adds a flat 0.5 labour hours per component and marks up delivery by 10% for addresses outside Toronto. Refine this function to reflect realistic labour time per component, actual material costs, and finish multipliers for different product families. Additionally, include any extra costs like installation fees or required deposits to make quotes more accurate.

* **Email notifications** – The email sending functionality uses a generic fallback (`quotes@moduvo.com`) if the `FROM_EMAIL` environment variable isn’t set, and it reads SMTP credentials from environment variables. Ensure all SMTP settings (host, port, user, password, from address) are correctly configured in the production environment. Customize the email templates with Moduvo branding (e.g. include the company logo and contact information) for a professional look. After configuring, test that notification emails send properly and avoid spam folders.

* **Admin role and security** – Several API routes (e.g. `/api/admin/quotes` and design routes) have **TODO** comments for admin-only access. Implement a role-based access control system so that only authorized admin users can view or modify all quotes and designs. For example, use JWT claims or a user role field to differentiate admins from regular users. This will secure the admin endpoints and prevent unauthorized access to sensitive data.

* **Authentication and sessions** – The front-end uses a `useAuth` hook that calls `/api/auth/user` to get the current user, implying a session or token-based auth. Make sure the authentication provider (Replit auth or another OAuth service) is properly configured and that user sessions persist across requests. Consider expanding login options beyond Replit (for instance, adding email/password or Google OAuth) to make signing up easier for a broad audience. Ensure that when users log in, their session is maintained (e.g. via secure cookies or JWT) so they remain authenticated while using the app.

* **Form validation and UX** – The quote request form uses **Zod** schemas and **react-hook-form** for validation. Expand the validation rules to cover all required fields and formats (for example, ensure postal/ZIP codes and phone numbers are in valid formats and that no required field is left blank). Display clear error messages next to any field that fails validation so the user knows what to fix. After a user submits the form, the app currently shows a thank-you message – in addition to that, consider sending an immediate confirmation email to the customer with their submission details for a better user experience.

* **AR/VR & 3D models** – The AR visualization feature uses WebXR with a fallback 3D viewer. To make this truly production-ready, prepare high-quality 3D models of your modules in GLB (for web/Android) and USDZ (for iOS) formats. Test the “View in AR” experience on both iOS and Android devices to ensure compatibility and performance. Hide or disable the AR button when WebXR isn’t supported by the browser to avoid confusion. Also, provide clear instructions for users on how to scan their room and place the model (as shown in your AR instructions overlay) so that even first-time AR users can follow along easily.

## Prepare for Production Deployment

* **Deployment method** – The current Replit preview (`*.repl.co` domain) is not ideal for production traffic or custom domain usage. Deploy the application using a more robust method: for example, use Replit’s deployment features or host the front-end on a platform like Vercel/Netlify and the Node.js API on a service like Railway, Fly.io, or Render. Set up a custom domain for the site and ensure DNS and SSL (HTTPS) are configured. Remember to include all necessary environment variables (such as `PORT`, `DATABASE_URL`, `SMTP_*` settings, `GCS_BUCKET`, `GOOGLE_APPLICATION_CREDENTIALS`, etc.) in the new hosting environment so the app can run properly. If moving away from Replit, make sure to redirect or handle the old \*.repl.co URL to your new domain.

* **Database & object storage** – Right now the app uses Drizzle ORM with (presumably) a local SQLite or some default database on Replit, and stores files (like product images or 3D models) on Google Cloud Storage. For production, set up a dedicated PostgreSQL database (for instance on Neon, Supabase, or another cloud Postgres provider) and run all necessary migrations there. Update your `DATABASE_URL` to point to this production database. Also configure a Google Cloud Storage bucket (or an alternative like AWS S3) for storing images and models, and provide the service account credentials (`GOOGLE_APPLICATION_CREDENTIALS`) in the environment so the app can upload/read files. Don’t forget to seed the production database with your initial data (you mentioned an `/api/init-data` route – use that or run a migration script to load initial product and component info).

* **Performance & security** – Serve the front-end as a static optimized build, possibly through a CDN, to improve load times. On the server/API side, enable appropriate CORS settings so that your front-end domain can communicate with the API securely. Implement basic security best practices: for instance, enable rate limiting on the API to prevent abuse, enforce CSRF protection on forms or use same-site cookies for session tokens, and require HTTPS for all client-server communication (especially if you’re not already covered by the hosting platform’s settings). These steps will ensure the app remains responsive and secure under real-world usage.
