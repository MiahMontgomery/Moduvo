# Extracting IKEA Modular Furniture Data for AR Integration

## Data Schema for AR-Ready Furniture Models

To integrate IKEA’s modular furniture into an AR platform like Moduvo, we propose a structured JSON schema capturing each product’s key attributes and variants. Each product (e.g., a KALLAX shelf, BESTÅ cabinet, or PAX wardrobe) is represented as an object with the following fields:

* **`series`** – The product line or system (e.g., `"KALLAX"`, `"BESTÅ"`, `"PAX"`).

* **`category`** – High-level category and subcategory (e.g., `"Shelving Units"` > `"Cube Storage"`, `"Storage Systems"` > `"Sideboards"`, `"Wardrobes"` > `"PAX System"`).

* **`name`** – Model name and basic description, often including dimensions or configuration (e.g., `"KALLAX shelf unit 147x147 cm"`, `"BESTÅ storage combo with doors 120x42x74 cm"`, `"PAX/HASVIK wardrobe combination 200x66x236 cm"`).

* **`dimensions_cm`** – Object with numeric dimensions for width, depth, and height (in cm) for the assembled product, for consistent AR scaling. For example: `"dimensions_cm": { "width": 147, "depth": 39, "height": 147 }` for a KALLAX 4x4 unit.

* **`materials`** – Key material composition (e.g., particleboard, fiberboard, foil finish) for realism in rendering. (For instance, KALLAX uses *“Particleboard, Fiberboard, Acrylic paint, Honeycomb paper filling...”*.)

* **`price`** – Current price (in a chosen currency, e.g., USD), useful for app display (e.g., `179.00` for KALLAX 4x4 shelf).

* **`variants`** – An array of variant objects, detailing available **colors/finishes**, **sizes/configurations**, and **product IDs**. Each variant includes:

  * **`color`** – Color or finish name (and door style if applicable). For example: `"White"` or `"White stained oak/Stubbarp white legs"`.
  * **`size`** – If the model has size options (e.g. PAX wardrobes with different heights or widths), specify dimensions or a label (e.g., `"200x66x236 cm"` vs `"200x66x201 cm"` for PAX tall vs short).
  * **`articleNumber`** – IKEA’s article ID for that variant (8-digit code, often written with periods). For consistency, we use the full 8-digit code (e.g., `"302.758.61"` for white KALLAX shelf unit, or `"095.606.95"` for a white PAX/HASVIK combo).
  * **`assetUrls`** – URLs for 3D assets, including **`glb`** (glTF binary) and **`usdz`** (USDZ for iOS AR). These files are web-optimized models for AR. (For example, a variant might have `"glb": "https://.../kallax-white-147x147.glb"` and a corresponding USDZ link.)
  * **`thumbImages`** – Array of image URLs (JPEG/PNG) for thumbnails or alternate views, to use as fallbacks or catalog images. These include front and angle views as provided on the product page (e.g., the set of product photos).

* **`configurableOptions`** – Any modular configuration notes (text or list). For instance, a PAX wardrobe might list compatible **interior organizers** (KOMPLEMENT drawers, shelves) or note if doors/handles are included. E.g., `"Interior accessories ( KOMPLEMENT series ) sold separately"`. KALLAX could note insert boxes that fit its cubes. This helps dynamic querying of compatible parts.

* **`warranty`** – Warranty info if applicable (e.g., `"10-year limited warranty"` for PAX system).

* **`categoryTags`** – (Optional) Tags for quick filtering, e.g., `["Storage", "Wall-mounted", "Modular"]`.

The data emphasizes **consistency** (uniform units, keys) to streamline use in a WebXR + Three.js pipeline. All sizes use centimeters; all 3D models use glTF/GLB (with PBR materials) which Three.js can load directly, ensuring accurate scale and appearance in AR. USDZ counterparts are provided for AR Quick Look on iOS.

**Notes:** In the above JSON, the `assetUrls` are placeholders illustrating expected links. In practice, these can be obtained by **scraping IKEA’s public web content**. When a product has a “View in 3D” option on its page, the underlying GLB model can be found via the network calls or IKEA’s open APIs. For example, IKEA’s **rotera API** provides model links: a GET request to

```
https://web-api.ikea.com/{country}/{lang}/rotera/data/model/{itemId}
```

returns a JSON containing the URL to the `.glb` file (and sometimes a `.usdz`) for the given `itemId` (the product’s 8-digit ID). This is how community tools retrieve the models. (The Tampermonkey script **“IKEA 3D Model Downloader”** uses this method, adding a download button that fetches the GLB.) All assets are **open-access** – no credentials or private APIs are required – and are optimized for web AR (low-poly, “close enough” dimensions as noted by IKEA engineers).

Each product entry also includes high-quality thumbnail images from IKEA’s site (at least one per variant) for non-AR fallback or catalog browsing. These images cover multiple angles as provided under “All media” on the product pages. The combination of **3D models + metadata + images** in this structured format allows the Moduvo platform to **render the furniture in AR**, answer dimension/variant queries in real-time, and degrade gracefully to images if needed. The schema can be ingested into a database or used directly in front-end code to power interactive AR product previews, ensuring consistency across the experience.

**Sources:** The schema and sample data above are derived from IKEA’s publicly available product information and AR assets: KALLAX shelves, BESTÅ storage combinations, and PAX wardrobes, including their dimensions, materials, variant options and confirmation of AR model availability. This structured approach aligns with best practices for WebXR/Three.js integration and uses only open web data (no gated APIs).
